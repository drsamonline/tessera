The problem

Four to seven systems hold a slice of the same customer. The slices disagree.

Reconciling them costs a person a morning a week, and the reconciliation is invisible to everyone else. The usual answer is a migration: move everything into one CRM, lose two years of history in the edges, and repeat the exercise in five years.

01

No migration

Adoption is additive. The mesh connects to what exists and produces the first result before anything is moved. The native core is one node in the mesh, not the product.

02

One ledger

Every action in every connected system becomes one hash-chained event. “What did each system know at time T” has exactly one answer, and it is provable.

03

Seats, not users

Work is assigned to a position, not a person. A human or an agent fills it. Every agent seat must declare a fallback, and every handoff carries full state, signed.

How it works

Three moves, in this order.

STEP 1

Connect

A node joins with a capability manifest, a versioned schema map and a per-field authority map. Nothing is copied. Nothing is migrated.

STEP 2

Unify

One canonical schema, ten objects, four sync modes per field. Conflicts resolve by a declared order and are logged — never silently overwritten.

STEP 3

Prove

Every action lands in the ledger. Bi-temporal views and git checkpoints are projections of it, and a projection that cannot be rebuilt is a defect.

Architecture

Eight layers. Five are specified, three are roadmap with written entry criteria.

L0

Federation mesh v1

Nodes, canonical schema, four connectors, deterministic routing, universal ledger, conflict resolution.

L1

CRM core v1, optional

Reference implementation of the canonical schema. Local-first web, encrypted offline mobile.

L2

Workforce v1 subset

Seats, occupants, tasks, handoff packets, escalation ladders, two observable autonomy tiers.

L3

Intelligence v2

Graduated autonomy, workforce analytics with provenance, cost-aware routing.

L4

Protocol and settlement v3

Cross-company chains, agent-to-agent transactions, a universal dispute trail.

L5

Economic engine v3

Marketplace with provenance, outcome billing, revenue share for published org designs.

L6

Experience v1

Design system, jargon discipline enforced by lint, migration as an interface rather than a project.

L7

Learning v1

Bootcamp, coach, academy, documentation, changelog, community — ten artefacts, each with a criterion.

Non-negotiable

Three rules, each with a test. A rule without a test is a slogan.

1

No AI in the critical path

Read, write, sync, auth, search, report and notification work with every AI container switched off. The full test suite must pass at the bare profile.

2

Nothing is silently overwritten

A cross-system conflict resolves by a declared order and is written to the ledger with both candidate values and the rule that settled it.

3

History has one authority

The event ledger is the record. Bi-temporal columns, git checkpoints and graph projections are derived, and must be rebuildable from it.

What exists: a specification, an audit register, a metric dictionary, acceptance criteria, three rendered documents, and a dependency-free reference core — the canonical schema, the hash-chained ledger, every metric, routing, conflict resolution, the connector contract, the conformance suite, four connectors, backpressure, a working mesh, projections that rebuild from the ledger a workforce layer, an HTTP surface with an OpenAPI 3.1 contract, three-layer access control, a compliance substrate and local-first sync, under 692 tests. Reviewed: 13 findings, 11 fixed.

What does not exist: the product. No connector connects, no service listens, no interface renders, no workforce runtime runs. Every claim on this page outside the reference core is a requirement, not a feature.

What was corrected: the source document’s 30-day data-subject-request clock was a GDPR transplant and is now a per-jurisdiction configuration. Its 72-hour breach clock was right — DPDP Rules 2025, rule 7(2), requires it — and is retained.
